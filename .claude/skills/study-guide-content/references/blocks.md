# 블록 타입 9개

`modules[].blocks[]` 에 쓸 수 있는 전부다. `blocks.js` 의 `BLOCK_RENDERERS` 에 정의된
것만 렌더링되고, 모르는 타입은 콘솔 경고와 함께 문단으로 떨어진다.

perca 콘텐츠(12모듈) 실제 사용 빈도: `prose` 47 · `callout` 15 · `list` 10 ·
`equation` 8 · `diagram` 7 · `table` 3 · `qaList` 2 · `termGrid` 1 · `figureCard` 1.

산문이 수적으로는 많지만, **학습 효과를 끌어올리는 건 그림·도식·표 쪽이다.**
구조적 관계는 `diagram`, 비교와 숫자 모음은 `table`, 원문 그림은 `figureCard` 로
옮기는 데 공을 들여라. 고를 때의 기준은 "이 내용이 이 형태일 때 더 빨리 이해되는가"
하나다 — 그 답이 '아니오'면 `prose` 가 맞다.

---

## prose — 설명 문단

```json
{ "type": "prose", "text": "설명 문장. <b>강조</b>와 <sub>첨자</sub> 가능." }
```

기본값. 고민되면 이걸 쓴다.

## list — 목록

```json
{ "type": "list", "ordered": false, "items": ["항목 1", "항목 2"] }
```

`ordered: true` 면 번호 목록. **순서가 의미를 가질 때만** true — 절차·시간순 등.

## callout — 강조 상자

```json
{ "type": "callout", "tone": "blue", "text": "놓치면 안 되는 한 줄." }
```

`tone` 은 `"blue"`, `"teal"`, 또는 생략(기본). 한 모듈에 한두 개면 충분하다 —
전부 강조하면 아무것도 강조되지 않는다.

## termGrid — 용어 정의

```json
{ "type": "termGrid", "items": [ { "name": "엽록체", "def": "광합성이 일어나는 장소" } ] }
```

용어와 뜻을 나란히 놓는 2열 격자. 정의가 짧을 때 적합하다. 설명이 길어지면
`prose` 가 낫다.

## equation — 수식·반응식

```json
{ "type": "equation", "num": "식 (1)", "expr": "[RO2*] = ΔNO2 / CL",
  "meaning": "증폭된 NO2 변화량을 사슬길이로 나누면 원래 라디칼 농도가 나온다." }
```

`meaning` 은 **반드시 채운다.** 식만 있고 뜻이 없으면 외울 수가 없다 —
"이 식이 무엇을 말하는가"를 한국어 한 문장으로 쓴다.
`num`, `expr` 은 이스케이프되므로 HTML 태그가 그대로 글자로 보인다.

## table — 비교표

```json
{ "type": "table",
  "columns": ["구분", "고체", "액체", "기체"],
  "rows": [ ["입자 배열", "규칙적", "불규칙", "매우 불규칙"] ],
  "highlightRows": [0] }
```

`highlightRows` 는 강조할 행의 **0부터 세는 번호**. 외워야 할 핵심 행을 표시한다.
`columns` 는 이스케이프되고 `rows` 셀은 표기 규칙이 적용된다.

표가 가장 쓸모 있는 두 자리:

1. **비교** — 항목 3개 이상을 속성 2개 이상으로 견줄 때. 산문으로 늘어놓으면
   독자가 머릿속에 표를 다시 만들어야 한다.
2. **숫자 모음** — 외워야 할 수치를 한곳에 모을 때. 본문 여기저기 흩어진 숫자는
   반복 학습이 불가능하다. `perca-ceas.json` 의 `m4`(핵심 숫자 암기표)가 그 예로,
   장비·교정조건·성능·현장 네 묶음으로 17개 수치를 모았다.

첫 열은 묶음 이름(`구분`)으로 두면 행이 많아져도 읽힌다.

## figureCard — 그림 설명 카드

```json
{ "type": "figureCard", "items": [
  { "tag": "Fig. 2", "caption": "장비 구성도", "imageUri": null,
    "takeaway": "핵심은 증폭부와 검출부가 분리돼 있다는 점." } ] }
```

원문의 그림을 말로 설명할 때 쓴다. `imageUri` 는 보통 `null` —
이미지 파일을 저장소에 넣지 않는 이상 비워둔다.

`tag` 는 원문의 그림 번호 그대로(`Fig. 2`, `그림 3-1`) — 발표나 시험 중에 원문을
펼쳐 대조할 수 있어야 하므로 번호를 지어내지 않는다. `caption` 은 그림이 무엇을
보여주는지, `takeaway` 는 **"이 그림에서 가져갈 한 줄"** 이다. 셋 중 `takeaway` 가
가장 중요하다 — 그림을 봤다는 것과 그림이 말하는 바를 아는 것은 다르다.

원문에 그림이 여러 개면 **그림 전용 모듈**을 따로 두는 편이 낫다. `perca-ceas.json`
의 `m6` 가 그 예로, 그림 6개를 각각 `diagram`(직접 다시 그린 도식) + `list`(해부
설명) + `callout`(한 줄 요약) 묶음으로 정리했다. 학습법 0단계가 "그림부터 보기"라
이 모듈이 통째로 1단계 교재가 된다.

## qaList — 예상 문답

```json
{ "type": "qaList", "items": [ { "q": "왜 챔버 압력을 낮추나요?", "a": "..." } ] }
```

접었다 펴는 문답. **발표 예상질문이나 시험 서술형**에 맞다.
단답 암기는 `cards` 쪽이지 여기가 아니다 — 카드는 간격 반복이 붙지만 이건 안 붙는다.

## diagram — 도식

```json
{ "type": "diagram", "svg": "<svg viewBox=\"0 0 400 200\">…</svg>",
  "caption": "라디칼 증폭 사슬" }
```

인라인 `<svg>` 를 **직접 그린다**(`imageUri` 도 가능하지만 보통 svg). 원문 그림을
파일로 가져올 수 없으니, 구조를 이해한 뒤 다시 그리는 셈이다. 흐름도·순환도·장치
구성도처럼 **글로 설명하면 장황해지는 관계**에서 값어치가 가장 크다.

그릴 때 지킬 것:

- **색은 하드코딩하지 않는다.** `fill="#333"` 으로 쓰면 다크 모드에서 글자가
  배경에 묻혀 사라진다. CSS 변수를 쓴다: `fill="var(--ink)"`,
  `stroke="var(--blue)"`, `fill="var(--surface)"`.
  쓸 수 있는 변수: `--ink`, `--ink-soft`, `--ink-faint`, `--surface`,
  `--surface-soft`, `--line`, `--blue`, `--orange`, `--teal`, `--red`, `--gray`
  (각 색엔 `-soft` 변형도 있다 — 배경 채우기용).
- **`viewBox` 를 반드시 넣고 `width`/`height` 는 넣지 않는다.** 그래야 화면 폭에
  맞춰 줄어든다. 모바일에서도 봐야 한다.
- **글자는 12px 이상**(`font-size="13"` 정도). 도식 안 글자가 작으면 폰에서 못 읽는다.
- **화살표에는 라벨을 단다.** 화살표만 있고 그 위에 무엇이 일어나는지 안 적혀 있으면
  그림이 절반만 말하는 셈이다.
- 요소 개수는 **7개 안팎**까지. 그보다 많아지면 그림이 글보다 어려워진다 —
  그럴 땐 두 개로 쪼갠다.

`caption` 은 그림이 말하는 바를 한 문장으로 쓴다. 그림만 있고 캡션이 없으면
"그래서 뭘 보라는 건지"를 독자가 추측해야 한다.

`sanitizeHtml()` 이 svg 안의 `<script>` 와 `on*` 핸들러는 제거하지만, 도형과
`viewBox`·`fill` 같은 속성은 그대로 둔다.
